🎯 Goals

Build a clean, modern, maintainable Neovim configuration from scratch that serves as a professional development environment for a polyglot programmer working across C#, Python, TypeScript, Rust, Lua, and Bash. The config should:

  • Use only current, non-deprecated APIs (Neovim 0.11+ native LSP, no legacy lspconfig framework)
  • Be understandable — no magic, every decision documented with a reason
  • Be easy to extend — adding a new language should take 5 minutes
  • Be reliable — prefer battle-tested plugins over novelty
  • Match VSCode muscle memory where it makes sense, without being a VSCode clone
  • Teach Neovim Lua config patterns as we build it

📁 File & Folder Structure

Clean separation of concerns. Each plugin gets its own file. No monolithic config files.

~/.config/nvim/
├── init.lua -- entry point, loads config/ then lazy
├── lazy-lock.json -- auto-generated lockfile (commit this)
└── lua/
├── config/ -- core vim settings (no plugins)
│ ├── options.lua -- vim.opt.*, UI options
│ ├── keymaps.lua -- non-plugin keymaps
│ └── autocmds.lua -- autocommands (highlight on yank, etc)
└── plugins/ -- one file per plugin or category
├── ui/
│ ├── colorscheme.lua -- tokyonight
│ ├── lualine.lua -- statusline
│ ├── bufferline.lua -- tab bar
│ ├── dashboard.lua -- start screen (snacks.dashboard)
│ └── noice.lua -- command line / notifications UI
├── editor/
│ ├── treesitter.lua -- syntax, folding, indentation
│ ├── neo-tree.lua -- sidebar file explorer
│ ├── snacks.lua -- picker, terminal, words, indent, bigfile
│ ├── gitsigns.lua -- inline git hunk indicators
│ ├── neogit.lua -- git status / commit UI
│ ├── which-key.lua -- keybinding hints popup
│ └── mini.lua -- mini.pairs, mini.surround, mini.ai
├── lsp/
│ ├── mason.lua -- package manager for servers/tools
│ └── lspconfig.lua -- vim.lsp.config + vim.lsp.enable calls
├── completion.lua -- blink.cmp
├── formatting.lua -- conform.nvim
├── linting.lua -- nvim-lint
├── debugging.lua -- nvim-dap + nvim-dap-ui
└── ai.lua -- avante.nvim
Why this structure? lazy.nvim automatically scans lua/plugins/ for any .lua files and loads them. You never have to manually import plugin files — just create a file and it gets picked up. The config/ folder is loaded explicitly from init.lua before lazy starts.

📦 Plugin Manager: lazy.nvim

Choice: lazy.nvim — the current standard. Used by LazyVim, AstroNvim, and most modern configs.

Why lazy.nvim

  • Lazy-loads plugins by event, command, or keymap — fast startup
  • Beautiful UI (:Lazy) showing load times per plugin
  • Lockfile (lazy-lock.json) for reproducible installs
  • First-class support for local plugins and dev mode
  • Actively maintained by the same author as many top plugins

Alternatives considered

  • packer.nvim — archived, do not use
  • vim-plug — still works, but no lazy-loading, Vimscript
  • rocks.nvim — interesting future, not yet mainstream
Bootstrap pattern: lazy.nvim installs itself on first launch via a short snippet in init.lua. No manual install step needed.

🔧 LSP Setup

Important — API change in Neovim 0.11+: The old require('lspconfig').pyright.setup({}) pattern is deprecated and will be deleted. Your config will use the new native API: vim.lsp.config() + vim.lsp.enable(). nvim-lspconfig is still installed but only as a data source — it provides server definitions that Neovim's built-in LSP client reads automatically from its lsp/ directory.

How the new API works

-- Tell Neovim how to configure a server (merge with its lspconfig defaults):
vim.lsp.config('lua_ls', {
  settings = {
    Lua = { workspace = { checkThirdParty = false } }
  }
})

-- Enable auto-activation for that server:
vim.lsp.enable('lua_ls')

-- Apply capabilities to ALL servers (e.g. from blink.cmp):
vim.lsp.config('*', {
  capabilities = require('blink.cmp').get_lsp_capabilities()
})

💻 Terminal Integration

Using snacks.terminal — a floating terminal toggled with Ctrl-\ or <leader>ft. It remembers its state between toggles (the shell process stays alive). No separate toggleterm plugin needed.

Since you use tmux alongside Kitty, the floating terminal inside Neovim is for quick one-off commands — running tests, git push, etc. For longer terminal sessions you can use your tmux panes directly. This keeps the boundary clean.

🤖 AI Tooling — avante.nvim

Recommendation: avante.nvim with Claude Sonnet. This is the closest thing to Cursor inside Neovim — it gives you a side panel to chat about code, inline diffs you can apply with a keypress, and agentic tool use.

avante.nvim

Cursor-like sidebar + inline edits. Supports Claude, GPT, Copilot, Gemini, and local models. You already use Claude, so this is a natural fit.

🚀 Installation Steps (Pre-config)

These are steps to complete before writing any config code. Most are likely already done.

1

Verify Neovim version

nvim --version   # must be 0.10+, you have 0.12.2 ✓
2

Verify Nerd Font in Kitty

Open Kitty and run echo "" — you should see a Nerd Font icon, not a box. MesloLGL is confirmed installed. Set it in Kitty config: font_family MesloLGL Nerd Font

3

Install Rust via rustup (if not already done)

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup component add rust-analyzer
4

Install build dependencies for blink.cmp (Rust compilation)

brew install cmake   # if not present
5

Install ripgrep and fd (required by snacks picker)

brew install ripgrep fd
6

Backup existing (empty) config

mv ~/.config/nvim ~/.config/nvim.bak 2>/dev/null || true
7

Set ANTHROPIC_API_KEY in shell

# Add to ~/.zshrc or ~/.bashrc:
export ANTHROPIC_API_KEY="your-key-here"

⚠️ Risks, Tradeoffs & Alternatives

Risk / TradeoffMitigation
vim.lsp.config API is very new — fewer tutorials online We will write fully documented code. Official Neovim docs are the authoritative source.
blink.cmp requires a Rust build step lazy.nvim handles this automatically. If it fails, we fall back to the Lua implementation (one config line change).
snacks.picker vs Telescope — less ecosystem history snacks.picker is made by folke (lazy.nvim author), very actively maintained. If a feature is missing, Telescope is a drop-in alternative.
avante.nvim is fast-moving — APIs change frequently lazy-lock.json pins the exact version. We upgrade explicitly, not automatically.
Unity C# debugging is complex (Mono vs .NET Core) Base C# debugging with netcoredbg works for non-Unity code. Unity debugging is scoped as a future optional step.
noice.nvim can occasionally conflict with other UI plugins Easy to disable — it is isolated in its own file. The rest of the config works without it.
Many plugins from same author (folke) — single point of failure All folke plugins are best-in-class and have large communities. Alternatives documented above for each.
