Config Structure

Everything lives in ~/.config/nvim/. Plugins are organized by category — adding a new one is just creating a file in the right folder.

~/.config/nvim/ ├── init.lua Entry point — loads everything in order ├── GUIDE.html This file ├── .gitignore ├── lazy-lock.json Plugin lockfile — commit this │ ├── lua/config/ │ ├── options.lua Core vim settings │ ├── keymaps.lua Non-plugin keymaps │ └── autocmds.lua Autocommands │ └── lua/plugins/ ├── ui/ colorscheme, lualine, bufferline, snacks, noice, scrollbar ├── editor/ treesitter, neo-tree, which-key, mini, gitsigns, neogit, trouble ├── lsp/ mason, lsp, blink.cmp, conform, lint ├── debug/ nvim-dap, dap-ui (Python / TS / C# / Rust) └── ai/ avante.nvim + Claude Sonnet

How lazy.nvim loads plugins: init.lua tells lazy to scan each plugins/X/ directory. Every .lua file in those directories is treated as a plugin spec automatically.

Adding a Plugin

Create a .lua file in the appropriate lua/plugins/X/ folder and return a spec table. Restart Neovim — lazy.nvim installs it automatically.

-- lua/plugins/editor/my-plugin.lua
return {
  "author/plugin-name",
  event = "VeryLazy",   -- when to load
  opts  = {            -- passed to require("plugin-name").setup(opts)
    some_option = true,
  },
}
FieldPurpose
eventWhen to load: "VeryLazy", "BufReadPre", "InsertEnter"
cmdLoad when command runs, e.g. "Neotree"
keysLoad when keymap is pressed
ftLoad for specific filetypes only
dependenciesOther plugins that must load first
buildRun once after install: ":TSUpdate", "make"
optsPassed directly to .setup()
configFull setup function when you need more than opts

Rust is special: rust-analyzer must match your active toolchain. Install it with rustup component add rust-analyzer — never via Mason.

To add a new server: open :Mason, press i to install, then add it to ensure_installed in mason.lua and configure it in lsp.lua.
